# 固定噪音與掃頻對照

手機在 Hub 前方播放 noise_vs_sweep_29s.wav，沿用相同位置及音量。使用者確認前輪完整播放固定噪音。此次為 WASAPI 獨佔模式。

前輪共享模式錄音在相鄰的 20261122_165407_301555_mic_check。共享模式下三軌的固定噪音均逐漸被壓低，其中 B 軌在錄音第 24～27 秒全為零，掃頻則保持可見。這個模式下回報的串流錯誤旗標仍為空，說明沒有溢位旗標不能代表音訊內容未被處理。

本輪獨佔模式三軌均持續錄到固定噪音，無滿幅樣本或串流錯誤。以 200～8000 Hz 頻帶計算，排除明顯低頻成分後的結果如下。

| 軌道 | 安靜段 dBFS | 沙沙聲後段 dBFS | 掃頻後段 dBFS |
| --- | --- | --- | --- |
| A | -68.2 | -52.9 | -54.4 |
| B | -69.1 | -54.9 | -56.5 |
| C | -69.6 | -54.1 | -55.6 |

錄音內比較區間為安靜段 5～15 秒、固定噪音後段 24～27 秒、掃頻後段 37～40 秒，依可見的共同播放事件選定。這些數值包含手機頻率響應、麥克風位置、房間聲學及麥克風本身差異。

Windows 為三個輸入端點掛上同一個 Voice Clarity 音效元件。AGC 已關閉、三軌增益相同，Disable_SysFx 屬性也已設成 1，但共享模式仍出現抑制。獨佔對照支持問題與共享音訊路徑有關，尚未單獨確認 Voice Clarity 是否為唯一原因。

正式 voice.cmd record 已改為預設獨佔模式，並保留 --shared 供比較。本輪未變更或移除 Windows 音效驅動，未驗證實體定位角度或聲紋正確率。
